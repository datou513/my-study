# 我怎么写代码

> 这份文档解决一个具体问题：**思路有了，打开编辑器不知道从哪下手。**
> 根因不是语法，是"自然语言还没降到数据结构"。

---

## 五步

### 1. 只写签名

```python
def split_markdown(content: str, doc_title: str) -> list[BlockDraft]:
```

签名逼你回答：吃什么、吐什么、有没有副作用。
**写不出签名 = 思路还没想清，这时候不要打开编辑器。**

### 2. 列"我需要记住什么"

把过程里要跨行保持的状态全部列出来。

```
标题栈 [(1,"深度学习"),(2,"第3章")]
段落缓冲 [...]
是否在代码块 True/False
```

这几样就是变量清单。**先列完再写代码**，否则会边写边加变量，最后状态散落。

### 3. 把过程写成编号中文

```
1. 逐行扫描
2. 遇到围栏 → 翻转 in_code
3. 遇到标题 → flush，再弹栈/压栈
4. 空行 → 段落结束
```

编号步骤**一比一对应代码分支**。写不出这几行，说明还没想清。

### 4. 先写最小可跑版本

只处理 happy path，二十行也行。跑通了再加边界。
**能跑的一百行胜过跑不起来的五百行。**

### 5. 逐个加边界，一个边界一条测试

按出现频率排序，不是按你想到的顺序。测试写在实现前面。

---

## 每写一个新函数，先交三样

不超过 15 行，确认后再写实现：

1. 签名（含类型注解）
2. 变量清单
3. 编号步骤

## 什么时候算"想清了"

四条都能答上来：

- 输入 / 输出 / 副作用各是什么
- 所有需要跨行保持的状态都列出来了
- 编号步骤里每一步都能对应到一个代码分支
- 能说出至少 3 个边界情况

---

## 卡住时的三个动作

1. **自顶向下写调用**：`pieces = _split_long(text)`，函数不存在也先写着，把主流程写成"读起来是对的"，再补实现。
2. **中文注释占位**：写不出代码就先写一行中文注释，然后翻译它。**翻译比构思容易。**
3. **缩小到能跑**：把卡住那段单独放进 `tmp.py`，喂几个数据 `print` 出来。不要在 600 行文件里盲调。

## 学习日志

### 2026-11-12 · 切块 `split_markdown`

- **思路**：一行行扫，按标题分段，按字数合块
- **卡点**：代码块里的空行会被当成段落分隔；超长段落不知道切在哪
- **破局**：加 `in_code` 布尔值跳过空行判断；切点用 `_find_cut` 在窗口内找句末标点
- **事后看**：最该早做的是"先拆单元再攒块"。混着写时同一个判断在三个分支里重复，说明缺一个中间表示
- **教训**：同一个判断重复出现三次，不是代码啰嗦，是数据结构没设计好
