# ADR-0001：三个存储各管一件事

- 状态：已接受
- 日期：2026-11-10

## 背景

需要存四类数据：原始文件（PDF、图片）、元数据与正文、块向量、以及将来的用户与权限。
单用户、数据量在十万块以内。

## 决定

- **MinIO** 存原始文件，key = 内容 sha256，不可变。
- **MySQL** 存元数据、块文本、笔记正文、断言、题目、作答。
- **Milvus** 只存向量与最小过滤字段，**不备份**。

## 理由

1. 原始文件与派生数据分离，任何一层坏了都能从另一层重建。
2. Milvus 是纯派生数据，备份它等于备份一份随时能重算的东西。
3. MySQL 的 ngram 全文索引可以直接承担词法召回，省掉一个 ES。
4. 这三个组件都是简历/面试里会被问到的，练手价值与使用价值一致。

## 代价

- 三套状态，备份策略要分开（MinIO `mc mirror` + MySQL `mysqldump`）。
- Milvus 与 MySQL 之间没有事务，一致性靠"块先落 MySQL，再 upsert 向量"的顺序保证。
- 迁移到 NAS 时要搬数据卷，不能只 `git clone`。

## 备选方案

- Postgres + pgvector（少一套系统，但少了三样要练的东西）
- SQLite + sqlite-vec（最简，但多端访问困难）
